# Плагин Read Receipts для Mattermost

Плагин `com.mattermost.plugin-readreceipts` в стиле официального дизайна Mattermost
«Read receipts for DMs/GMs»: у отметки времени сообщения стоят галочки — одна серая
(сообщение на сервере) или две синие (прочитано), — а по клику открывается карточка
со статусами и временем.

Минимальная версия сервера — **11.9.0**: галочки выводятся штатным хуком веб-части
`registerPostHeaderComponent`, он появился в 11.9. Проверено на 11.11.1 (React 18)
и 12.0.0 (React 19).

Окно статусов выводится порталом `createPortal`, а не `ReactDOM.render`: в React 19
(с Mattermost 12) этих функций больше нет, и плагин падал с «Произошла ошибка в
плагине» при открытии окна.

## Что видит пользователь

| Элемент | Поведение |
|---|---|
| Галочки у времени | Одна серая — прочитавших нет; две синие — сообщение прочитали. В группах и каналах рядом число прочитавших |
| Карточка в личных сообщениях | Две строки: «Прочитано — сегодня 16:47» (синие галочки) и «Отправлено — 16:45» (серая) |
| Карточка в группах и каналах | Заголовок «Прочитали N из M» и список участников с временем прочтения, с догрузкой по кнопке «Показать ещё» |
| Переход в личные | Клик по человеку в списке открывает переписку с ним |

Галочки в шапке стоят у первого сообщения группы. У остальных сообщений той же
группы (подряд идущих сообщений одного автора) шапка в Mattermost скрыта, поэтому
плагин дорисовывает галочки прямо в строку сообщения — в конец последнего абзаца
текста, как в мессенджерах. Так статус виден у каждого сообщения, а не только у
первого.

Пункта «Прочитали» в меню поста (он был в 0.1.x) больше нет: в Mattermost 11 меню
переехало на MUI, и плагинные пункты в нём не отрисовываются — ни старый
`registerPostDropdownMenuComponent`, ни новое `registerPostDropdownMenuAction`
(проверено на 11.11.1). Рабочая точка входа — галочки.

**Чего плагин не умеет** (и не сможет): показывать состояния «отправляется» и
«доставлено получателю». Первое — состояние композера, которого ещё нет на сервере,
второе Mattermost нигде не хранит. Поэтому состояний два, а не четыре, как в макете.
В мобильном приложении плагины веб-части не загружаются вообще.

## Сборка

Полная сборка на Linux (серверные бинарники под Linux, Windows, macOS и веб-часть):

```bash
make dist
```

Веб-часть отдельно:

```bash
cd webapp
npm install
node node_modules/webpack/bin/webpack.js --mode production
```

Штатная команда `npm run build` может упасть с `webpack: Permission denied`, если
каталог `node_modules` скопирован с Windows и в нём не выставлен бит выполнения.
Вызов webpack через `node` работает всегда.

**Бит выполнения у серверного бинарника.** В архиве плагина файл
`server/dist/plugin-linux-amd64` должен иметь права `0755`. Архивы, собранные в
Windows-каталоге (там права записываются как `0666`), Mattermost загружает, но не
может запустить: в логе появляется `unable to start plugin: ... permission denied`,
а плагин остаётся выключенным. Перед упаковкой проверьте права:

```bash
chmod +x server/dist/plugin-linux-amd64
tar -tvzf dist/plugin-readreceipts-0.2.2.tar.gz   # ожидается -rwxr-xr-x
```

## Тесты

```bash
go test ./...                            # настройки из манифеста, область показа, порядок страниц
node webapp/test/position.test.mjs       # геометрия окна (57 проверок)
cd webapp && npm test                    # то же самое
```

Тест `TestConfigurationKeysFromPluginJSON` сверяет json-теги структуры
`configuration` с ключами `settings_schema` из `plugin.json`: если ключи перестанут
совпадать, настройки молча вернутся к значениям по умолчанию, и тест это поймает.
`TestReaderViewHasNoPrivateFields` не даёт вернуть в ответ почту, роли и прочие поля
профиля.

## Установка

```bash
mmctl plugin add --force plugin-readreceipts-0.2.2.tar.gz
mmctl plugin enable com.mattermost.plugin-readreceipts
```

или **System Console → Plugin Management → Upload Plugin** с подтверждением
перезаписи (плагин без подписи).

Флаг `--force` нужен при обновлении: на Mattermost 11.11.1 команда без него
отвечает «A plugin with the same ID is already installed». Через веб-интерфейс
перезапись подтверждается галочкой в окне загрузки.

Архив плагина собирается из `plugin.json`, `server/dist/plugin-linux-amd64` и
`webapp/dist/main.js`. Перед повторной выкладкой нужно поднимать `version` в
`plugin.json` — Mattermost не обновляет плагин с той же версией.

## Галочки у каждого сообщения группы

Mattermost склеивает подряд идущие сообщения одного автора: шапка с автором и
временем остаётся только у первого, у остальных она в DOM есть, но схлопнута в
ноль по высоте. Хук `registerPostHeaderComponent` рисует галочки только в шапке,
поэтому раньше статус был виден лишь у первого сообщения группы.

Отдельного хука «для каждого поста» в API плагинов нет (`registerPostActionComponent`
— это кнопка в панели действий при наведении). Поэтому корневой компонент
`InlineReadTicks` находит посты ленты, у которых шапка не видна (`height === 0`), и
дорисовывает галочки через портал в конец последнего абзаца текста. Первое
сообщение группы не трогается — там галочки остаются в шапке.

Детали, важные при сопровождении:

- признак «продолжение группы» — **нулевая высота шапки**, а не её отсутствие:
  в 11.11.1 `.post__header` есть у всех постов;
- если сообщение заканчивается списком, таблицей или кодом, галочки ставятся
  отдельной строкой под блоком (внутрь `<ul>`/`<pre>` вставлять нельзя);
- рисуются только посты в поле зрения (`IntersectionObserver`, запас 250 px),
  иначе на длинной истории получаются сотни порталов;
- статусы таких галочек опрашиваются реже — раз в 60 секунд и только при видимой
  вкладке; галочки в шапке продолжают обновляться раз в 15 секунд;
- при появлении сообщения в ленте плагин отмечает его прочитанным, поэтому время
  первого прочтения теперь фиксируется у каждого показанного сообщения, а не
  только у первого в группе.

## Время прочтения

Время фиксируется **один раз** — в момент, когда сообщение впервые появилось у
получателя. Клиент получателя сообщает об этом плагину (`POST /api/v1/read`), сервер
пишет отметку в KV-хранилище и больше её не меняет.

Раньше показывалось `LastViewedAt` участника канала — оно обновляется при каждом
заходе в переписку, поэтому время в окне «Прочитали» уезжало вперёд при каждом
открытии чата.

Отметки живут 180 дней; у сообщений, прочитанных до установки этой версии, время
фиксируется при первом открытии окна со списком и дальше тоже не меняется.

## Настройки

**System Console → Plugins → Read Receipts.**

| Ключ в plugin.json | Тип | По умолчанию | Что делает |
|---|---|---|---|
| `ChannelScope` | all / direct | all | Где показывать галочки: во всех каналах или только в личных и групповых (как в макете) |
| `DisplayLimit` | число | 10 | Сколько человек отдаётся за одну страницу списка |
| `DisplayNameFormat` | fullname / nickname / username | fullname | Как выводится имя в списке |
| `PopupPosition` | above / below / left / right | above | С какой стороны от галочек раскрывается карточка («над галочками» — как в макете Mattermost) |

Если с выбранной стороны карточка не помещается целиком, она показывается с другой
стороны; галочки она не перекрывает ни при каком положении.

Значения проверяются на сервере: пустое или неизвестное значение заменяется
значением по умолчанию. В канале вне области показа сервер вообще не перебирает
участников — только сообщает веб-части, что рисовать нечего.
